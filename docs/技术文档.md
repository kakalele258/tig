## 二、系统架构

整套算法是插件化流水线，每个插件单线程循环，插件间通过 latest-only 通道/缓冲传递数据：

```
ReceiveDecoder(ECSData) ─┐
                         ├─→ CameraManager ──→ InputFrame ──→ NNDetector ──→ TrackerManager ──→ PlannerControl ──→ SendEncoder
相机来源(回放/TCP图像) ──┘
```

| 插件 | 库 | 职责 |
| --- | --- | --- |
| `ReceiveDecoder` | `libreceive_decoder_plugin_lib.so` | 串口/仿真电控数据 → `ECSData`（模式、颜色、yaw/pitch/roll、start/ready） |
| `CameraManager` | `libsingle_camera_manager_plugin_lib.so` / `libdaedalus_camera_manager_plugin_lib.so` | 产 `InputFrame{ecs_data, timestamp, img}` |
| `NNDetector` | `libNNdetect_lib.so` | OpenVINO 推理，输出靶位五关键点 + 类别 + 置信度 |
| `TrackerManager` | `libtracker_manager_plugin_lib.so` | 位姿重建、相位/运动估计 |
| `PlannerControl` | `libfire_control_system_plugin_lib.so` | 弹道解算、火控状态机 |
| `SendEncoder` | `libsend_encoder_plugin_lib.so` / `libdaedalus_send_encoder_plugin_lib.so` | 结果下发（串口/仿真 UDP） |

关键接口定义在 `src/core/app/interface/`：

```cpp
struct InputFrame { ECSData ecs_data; timetool::Timestamp timestamp; cv::Mat img; };
struct FireResult  { AimMode mode; double yaw, pitch; bool is_find_target,
                     is_enable_fire, is_find_buff, is_keep_shooting; };
```

## 三、第 1 题：待激活 / 已激活灯效识别

### 3.1 模型

- 网络：姿态估计型检测网络，输入 `640x480`，输出 `[N, C, A]`，`A = 6300` 个 anchor。
  - anchor 数校验：`80x60 + 40x30 + 20x15 = 6300`，与 YOLO 三尺度特征图一致。
- 每个 anchor 输出：4 个框参数 + 1 个类别 + 5 个关键点（x, y, score）→ `C = 4 + 1 + 15 = 20`。
- 类别语义（`m_class_count = 3`）：**0 = 未击打（待激活）、1 = 已击打（已激活）、2 = 符心**。
- 推理后端：OpenVINO CPU，`device=CPU`，`conf=0.65`、`kconf=0.5`、`nms=30`、`min_valid_kpts=5`。

### 3.2 后处理

1. 逐 anchor 取最大类别分，低于 `confidence_threshold` 丢弃；
2. 关键点分低于 `keypoint_confidence_threshold` 的点标记无效，有效点少于 `min_valid_keypoints` 丢弃；
3. 按 IoU/中心距做 NMS（`nms_distance_threshold`）；
4. 类别 -> 灯效语义映射后画框（绿 = 待激活，红/橙 = 已激活），并标注关键点与置信度。

## 四、第 2 题：相机接入与实时显示

三种图像来源共用同一个 `InputFrame` 出口，下游无感知：

| 来源 | 插件 | 说明 |
| --- | --- | --- |
| 回放 | `ReplayCameraManager` | `cv::VideoCapture` 读 `big_rune_demo.mp4`，可循环、可限速 |
| 真实相机 | （预留） | WSL 下 usbipd 直通存在帧截断问题，未采用 |
| 仿真 | `DaedalusCameraManager` | 自研 TCP 客户端接收 Daedalus 图像流 |

### 4.1 仿真图像协议（Daedalus talos tcp_image v1）

64 字节大端头 + payload：

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | u32 | magic = `0x54494D47` |
| 4 | u16 | version = 1 |
| 6 | u16 | header_bytes = 64 |
| 8 | u16 | format（1 = RGB24，2 = RGBA32） |
| 10 | u16 | flags = 0 |
| 12/16/20 | u32 | width / height / payload_bytes |
| 24/32/40 | u64 | producer_epoch / source_sequence / capture_timestamp_ns |
| 48/56 | u64 | reserved |

分辨率 `1440x1080`，`RGBA32` 时单帧 `6,220,800` 字节。

### 4.2 接收器实现要点

- 自研 `DaedalusImageReceiver`，不用 SDK 自带客户端：SDK 的阻塞 `recv` 无法从外部中断，一旦链路异常会永久卡死插件线程。
- `SO_RCVTIMEO = 300ms`；连续 `5s` 收不到完整帧就 `shutdown + close` 并自动重连。
- `wait_frame()` 在插件内阻塞等待，保证每个流水线 tick 都有新帧——
  否则 `process()` 提前返回会让下游插件等不到数据，**整条流水线永久停滞**（这是本项目踩过的最深的坑）。

### 4.3 实时显示

`visualize = 1` 时通过 `img_viz` 统一 `cv::imshow`，输出 5 个窗口：
`RuneDemo/EndToEnd`、`Rune/NNDetector`、`PowerRune/Contours`、`PowerRune/BinaryMask`、`PowerRune/Projection`。
WSLg 下窗口正常显示；截图需从 Windows 侧用 `PrintWindow` 抓取（WSLg 窗口不在 X11 顶层树里）。

## 五、第 3 题：位姿解算与枪管转角

分三层，全部在 `src/core/algorithm/power_rune/`。

### 5.1 单靶位姿态（PnP）

- 检测到的五关键点 ↔ 靶位物理四角 + 灯心，用 `cv::solvePnP` + `IPPE` 求粗位姿 `R, t`。

### 5.2 符文平面重建（`PowerRunePlane`）

1. **多靶位 PCA** 拟合旋转平面 → 平面法向、符心、半径初值；
2. **非对称距离场 + Chamfer 残差**：把关键点投到平面模型上，度量到靶位轮廓的距离（比逐点欧氏距离稳定）；
3. **Ceres 6 自由度优化**：优化符文平面位姿，残差含锚点重投影误差 + 法向软约束，`DENSE_QR` 求解。

### 5.3 相位与运动估计

- 小符：卡尔曼滤波跟踪相位 `[θ, ω]`（匀速模型）；
- 大符：LM–IRLS 拟合相位-时间非线性模型（抗离群点，适应转速不恒定）；
- 输出：任意预测时刻的靶位位置。

### 5.4 弹道解算与枪管转角

1. 目标位置 `p_t`（由相位模型预测到命中时刻）；
2. 飞行时间 `t = |p_t - p_muzzle| / v`（`v = 25 m/s`，`g = 9.81`）；
3. `t` 依赖 `p_t` → **不动点迭代**收敛；
4. **RK4** 积分弹道（含重力下坠）；
5. 期望枪管朝向 - 当前云台角度 → **yaw/pitch 转角**；
6. 火控状态机判定 `ready/found/fire` 后置 `fire_advice`。

结果通过 `FireResult.yaw/pitch`（弧度制期望绝对角，0 = 水平）输出。

## 六、第 4 题：Daedalus 仿真部署

### 6.1 环境

- 模拟器：Daedalus 1.1.1（Windows，`bin\daedalus.exe`，DX12 高性能模式）
- 算法：WSL2 Ubuntu 22.04，`.wslconfig` 设 `networkingMode=mirrored`（使 WSL 可达 Windows 的 `127.0.0.1`）
- 端口：图像 TCP `5602`，云台 UDP `5601`，场景控制 UDP `5603`；Windows 侧中继 `5604`

### 6.2 坐标与单位约定（对接关键）

| 项 | 约定 | 我们的处理 |
| --- | --- | --- |
| yaw | 车体局部系绝对角，0 = 水平朝前，最大角速度 3 rad/s | 直接下发 |
| pitch | **90° = 水平**，>90 抬头，范围 45~135 | 下发 `pitch + 90`（clamp 45~135） |
| 内参 | `fx = fy = 1303.67532368147`，`cx = 720`，`cy = 540`，畸变全 0 | 单独一份 `config/power_rune_sim.json` |
| 弹道 | 初速 25 m/s，重力 9.81，弹丸直径 17mm | 与算法一致 |

### 6.3 为什么需要中继

WSL↔Windows 的 loopback（mirrored 模式）上，直连 `5602` 约 3 帧后必被断开；Windows 侧 .NET 客户端同条件 10 秒 351 帧稳定。
因此加一个 Windows 侧中继：上游始终全速读帧只保留 latest，下游按需写帧，天然容忍下游停顿。

### 6.4 待解决问题

Daedalus 的符文美术只有小部分姿态落进检测模型的分布：单帧仅 1 个靶位（`conf = 0.85~0.93`）或 0 个。
`PowerRunePlane` 需要多靶位锚点，因此平面重建无法启动，`found` 恒 0。
解决方向：为仿真单独训练检测头（`yolov8n-pose`，`kpt_shape = [5,3]`，1 类），anchor 布局与现模型一致，后处理无需改动。

## 八、已知限制

1. 仿真环境检测域差未解决（见 6.4）。

3. WSL 下真实 USB 相机经 usbipd 直通会截断帧，未采用。
